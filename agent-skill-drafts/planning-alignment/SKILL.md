# Planning Alignment

## When to Use

- 用户要求“规划一下”“先给方案”“不要改文件”“任务拆分”“实现计划”。
- 用户表达了自己的预期方案、禁止事项或改动范围。
- 一个任务存在 2 个及以上可行方案。

## Workflow

1. **Restate**：复述用户目标、用户倾向方案、禁止事项、可改动范围。
2. **Assumptions**：列出所有假设；不要把假设当事实执行。
3. **Scope**：列出预计修改的文件/模块，以及不应修改的文件/模块。
4. **Plan**：给出实现思路、边界情况、测试计划和需要确认的问题。
5. **Compare**：如果有多个方案，同时给出用户预期的最小改动方案和推荐工程化方案。
6. **Wait**：除非用户明确说“直接改”，否则等待用户批准后再执行。

## Constraints

- 不要静默切换到 agent 自己偏好的方案。
- 如果用户预期方案有风险，先说明原因并等待确认。
- 不要把项目专属命令、路径或模块名写进全局规划。
- 规划输出要具体到文件/模块和验证方式；不写空泛步骤。

## Output Shape

```markdown
## 目标

## 用户预期

## 范围

## 假设

## 方案

## 边界情况

## 测试计划

## 需要确认
```
