# Iterative Refinement

## When to Use

- 用户说方案不符合预期、结果不对、继续修、重新想。
- 需求存在歧义或关键约束缺失。
- 命令、测试、构建或实现失败。
- 同一问题已经尝试修复但没有收敛。

## Workflow

1. **Capture**：记录当前目标、失败现象、已尝试动作和真实输出。
2. **Diagnose**：做根因分析，区分需求误解、环境问题、实现问题、测试问题。
3. **Clarify**：只问会阻塞下一步的关键问题；能从上下文查到的不要问用户。
4. **Adjust**：给出修正方案，并说明和上一版方案的差异。
5. **Limit**：同一方向失败 3 次后停止重复尝试，提出替代路径或请求确认。
6. **Verify**：继续执行前说明验证方式；完成后报告真实验证结果。

## Constraints

- 不要无限重试。
- 不要用猜测替代澄清。
- 不要把失败包装成成功。
- 不要扩大改动范围来掩盖根因。

## Output Shape

```markdown
## 当前状态

## 根因判断

## 修正方案

## 需要确认

## 下一步验证
```
