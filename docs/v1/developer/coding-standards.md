# VectaHub 1.0 架构与开发规范 (Coding Standards)

> **版本**: 1.1.0
> **状态**: 基本准则
> **最后更新**: 2026-05-09

本手册定义了 VectaHub 1.0 的工程标准。开发与维护过程应遵循以下要求，以保持系统的隔离性与稳定性。

---

## 1. 架构要求

### 1.1 路径管理
- **原则**: 避免直接使用 `os.homedir()` 或硬编码的 `~/.vectahub` 路径。
- **实现**: 统一调用 `src/utils/paths.ts` 中的 `getVectaHubPath()` 方法。
- **目的**: 确保应用数据受 `VECTAHUB_HOME` 环境变量控制。

### 1.2 组件实例化
- **原则**: 核心组件应通过工厂函数创建，避免在业务代码中直接使用 `new`。
- **实现**: 使用 `createXxx()` 模式提供组件实例。
- **目的**: 降低耦合度，方便单元测试中的 Mock 注入。

### 1.3 类型定义
- **原则**: 领域类型应集中管理。
- **实现**: 类型定义存放在 `src/types/`，并由 `index.ts` 统一导出。

---

## 2. 工程与安全准则

### 2.1 JSON 响应协议
当子命令使用 `--json` 标志时，输出应符合以下结构：
- **成功**: `{ "ok": true, ... }`
- **失败**: `{ "ok": false, "error": { "code": "STRING", "message": "string" } }`

### 2.2 进程管理
- VS Code 插件启动的子进程需注册到 `ProcessManager`。
- 插件销毁时应调用清理方法关闭残留进程。

### 2.3 异常处理
- CLI 的全局错误应由 `src/cli.ts` 捕获并统一输出。
- 避免未捕获的异步 Rejection 导致进程非预期退出。

---

## 3. 开发约束
1.  **类型安全**: 尽量避免使用 `any`。
2.  **I/O 操作**: 在插件主线程中避免使用大文件的同步读写。
3.  **敏感信息**: 日志与代码中不得包含真实私钥或 Token。
