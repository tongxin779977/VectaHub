# P0-001: 统一 `run --dry-run --json` 输出 envelope

> Status: done
> Priority: P0
> Source: Architecture alignment
> Module: `src/commands/run-dry-run-envelope.ts`
> Completed: 2026-06-08

## Description

`run --dry-run --json` 输出使用 `RunDryRunEnvelope`，与项目标准的 `MachineResponseEnvelope` 结构不一致：

1. `RunDryRunEnvelope` 缺少 `schemaVersion` 和 `timestamp` 字段
2. `RunDryRunEnvelope` 包含冗余顶层字段（`reply`、`plan`、`userReport`、`steps`、`workflow`），与 `result` 判别联合中的数据重复
3. 两套 envelope 系统并存，增加维护成本和消费方理解负担

## Expected

dry-run JSON 输出 envelope 与 `MachineResponseEnvelope` 对齐：

- 包含 `schemaVersion: '1.0'` 和 `timestamp` 字段
- 移除冗余顶层字段，`result` 判别联合为唯一数据来源
- 保留 dry-run 特有字段 `dryRun: true` 和 `mode?`
- 保留 `intent?` 和 `dispatch?`（提供 `result` 之外的上下文）

## Scope

- In-scope: `src/commands/run-dry-run-envelope.ts` 类型定义和 builder 函数
- In-scope: `src/commands/run-dry-run-envelope.test.ts` 测试更新
- In-scope: `src/commands/run.dry-run.test.ts` 中对冗余字段的引用更新
- Out-of-scope: `MachineResponseEnvelope` 本身的修改（P0-006 范围）
- Out-of-scope: 非 dry-run JSON 输出格式
- Out-of-scope: `OrchestrationPlan`/`WorkflowDraft` 完整构造（P1-003/P1-005 范围）

## Verification Plan

1. 所有 dry-run JSON 输出包含 `schemaVersion: '1.0'` 和 `timestamp`
2. 所有 dry-run JSON 输出不再包含冗余顶层字段 `reply`、`plan`、`userReport`、`steps`、`workflow`
3. `result` 判别联合仍正确包含所有数据
4. Typecheck 通过
5. 所有相关测试通过
