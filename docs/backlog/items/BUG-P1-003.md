# BUG-P1-003: `resume` 执行记录中 workflowId 为 undefined

> Status: done
> Priority: P1
> Source: E2E Test T3 (Execution Records)
> Discovered: 2026-06-08
> Completed: 2026-06-08
> Module: `src/execution/record-manager.ts`

## Description

`vectahub resume <executionId>` 恢复失败执行时报错 "Workflow undefined not found"。执行记录中 `workflowId` 字段未正确保存，导致 resume 和部分 rerun 操作失败。

## Reproduction

```bash
npx tsx src/cli.ts resume exec_20260607_063441_ab0cf33b
```

## Expected

resume 从失败步骤恢复执行，或给出明确的恢复建议。

## Actual

```
❌ 运行时错误: Resume failed: Workflow undefined not found
```

## Additional Evidence

- `rerun exec_20260601_202017_bf2cfb8b` 报 "Workflow wf_49 not found"（工作流已被删除）
- `detail --step 0` 中 `Command: undefined`，说明步骤的命令信息也未正确保存
- 多个执行记录的 workflowId 字段缺失

## Impact

执行恢复（resume）功能完全不可用。rerun 对部分执行也不可用（工作流引用丢失）。

## Root Cause

两个根因：

1. **workflowId 为 undefined**：YAML 模板文件没有 `id` 字段，`loadWorkflowFromFile` 解析后 workflow 对象没有 `id`，导致引擎创建执行记录时 `workflowId: workflow.id` 为 `undefined`。
2. **步骤 command 为 undefined**：引擎创建的 `StepRecord` 没有 `command` 和 `stepName` 字段，但 `detail` 命令期望 `StepExecution` 类型有这些字段。`normalizeExecutionRecord` 仅做 spread 未做字段映射。

## Scope

- In-scope: `src/execution/record-manager.ts` 写入逻辑、执行记录 JSON schema
- Out-of-scope: 工作流删除策略（rerun 引用已删除工作流是预期行为）

## Verification Plan

1. 新执行完成后 `detail <id> --step 0` 显示正确的 Command
2. `resume <failed_id>` 能正确读取 workflowId 并恢复
3. 执行记录 JSON 文件包含 workflowId 字段

## Completion

### Changes

- `src/types/workflow.ts`: `StepRecord` 添加 `stepName?: string` 和 `command?: string` 可选字段
- `src/workflow/storage.ts`: `loadWorkflowFromFile` 为无 `id` 的 workflow 生成 `wf_file_` 前缀 id
- `src/workflow/engine.ts`: `runExecutionLoop` 在创建 `StepRecord` 时填充 `stepName` 和 `command`（成功和失败两个路径）
- `src/commands/run.ts`: 新增 `normalizeStepRecord` 函数，将 `StepRecord` 字段映射为 `StepExecution` 字段（`startAt`→`startedAt`、`endAt`→`finishedAt`、`output` 数组转字符串等）

- Typecheck: `npx tsc --noEmit` 通过（0 errors）
