# P2-011: 将 orchestration failure 接入 recovery loop

> Status: done
> Priority: P2
> Source: Architecture alignment
> Module: `src/types/orchestration-recovery.ts`, `src/commands/draft.ts`
> Completed: 2026-06-08

## Description

Orchestration execution failures need to enter a structured recovery loop rather than surfacing only as raw execution failure, so the system can classify the failure, produce a bounded recovery decision, and keep the recovery chain linked to the plan/draft/execution context.

The orchestration recovery model and tests already existed as pure contracts, but the draft execution command was not consuming them. This round connected failed draft execution into the recovery decision path and surfaced recovery records in the command result.

## Expected

- Classify orchestration failures from execution and verification outcomes.
- Produce structured orchestration recovery decisions for failed draft execution.
- Create orchestration recovery records linked to the failed execution context.
- Return recovery decision data instead of reporting all failures as generic command errors.

## Scope

- In-scope: orchestration recovery decision consumption by draft execution
- In-scope: recovery record creation on failed draft execution
- In-scope: JSON/human output for recovery suggestions
- Out-of-scope: a dedicated orchestration recover CLI command
- Out-of-scope: automatic fix execution beyond bounded recovery decisions

## Verification Plan

1. Failed execution or verification paths classify into orchestration recovery kinds.
2. Failed draft execution surfaces a recovery decision instead of a blind success path.
3. Recovery records retain plan/draft/execution linkage on failure.
4. Focused tests and static checks pass.
