# P1-010: 统一 human-readable 与 machine-readable response contract

> Status: done
> Priority: P1
> Source: Architecture alignment
> Module: `src/machine-response/index.ts`, `src/machine-response/human-readable-formatter.ts`
> Completed: 2026-06-08

## Description

The NL orchestration path needs a consistent response contract that serves both machine-readable consumers and human-readable CLI output without drifting into incompatible shapes.

The machine envelope and human formatter were already implemented across plan and draft responses. This round also revalidated the contract together with dry-run and draft-facing tests.

## Expected

- Build a stable machine response envelope with `schemaVersion`, `ok`, `result`, and `timestamp`.
- Support reply, clarify, blocked, validation, safety, internal-error, plan, and workflow-draft result kinds.
- Preserve consistent human-readable formatting for plan and draft outputs.
- Keep JSON output as a single valid object for command consumers.

## Scope

- In-scope: machine response envelope builders
- In-scope: plan and workflow-draft machine response formatting
- In-scope: human-readable formatting compatibility for orchestration outputs
- Out-of-scope: redesign of every legacy CLI command output
- Out-of-scope: UI-layer rendering outside CLI responses

## Verification Plan

1. Machine response builders emit the standardized envelope shape.
2. Dry-run orchestration responses preserve plan/draft contract shape.
3. Human-readable draft and plan output remain compatible with current command flows.
4. Focused tests and static checks pass.
