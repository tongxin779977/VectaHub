# P1-007: 实现 confirmation flow 最小闭环

> Status: done
> Priority: P1
> Source: Architecture alignment
> Module: `src/orchestration-plan/confirmation-handler.ts`, `src/commands/draft.ts`
> Completed: 2026-06-08

## Description

Plans and workflow drafts that require confirmation need a minimal state transition path so they can move from review output into executable or rejected states.

The confirmation handler and draft-facing confirmation flow were already implemented and covered by tests, but the backlog item file was missing.

## Expected

- Apply explicit confirmation decisions to `OrchestrationPlan`.
- Apply explicit confirmation decisions to `WorkflowDraft`.
- Support default non-interactive deny behavior.
- Preserve confirmation records on workflow drafts.

## Scope

- In-scope: plan confirmation state updates
- In-scope: draft confirmation state updates
- In-scope: non-interactive deny fallback
- In-scope: draft confirmation record persistence path
- Out-of-scope: interactive UI prompting
- Out-of-scope: policy-driven auto-confirm strategies beyond deny-by-default

## Verification Plan

1. Confirming all required tasks moves a plan to `ready`.
2. Denying any required task blocks the plan or cancels the draft.
3. Draft confirmation records persist with `confirmedBy` metadata.
4. Focused tests and static checks pass.
