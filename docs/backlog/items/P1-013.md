# P1-013: 将 confirmed WorkflowDraft 接入 workflow execution

> Status: done
> Priority: P1
> Source: Architecture alignment
> Module: `src/orchestration-plan/draft-executor.ts`, `src/commands/draft.ts`
> Completed: 2026-06-08

## Description

Confirmed workflow drafts need an execution bridge that validates execution eligibility, converts the draft into the existing workflow-engine structure, executes it, and links execution metadata back to plan/draft trace identity.

The execution bridge and CLI path already existed, but dedicated regression coverage and backlog tracking were missing. This round added the missing execution tests.

## Expected

- Validate that only confirmed or persisted drafts can execute.
- Convert a confirmed `WorkflowDraft` into a workflow-engine `Workflow`.
- Execute the converted workflow through the existing engine.
- Attach plan, draft, trace, and workflow-hash metadata to the execution record.

## Scope

- In-scope: draft execution bridge
- In-scope: draft-to-workflow conversion
- In-scope: execution-record trace and hash metadata
- In-scope: draft CLI execution entry
- Out-of-scope: recovery-loop integration for failed draft executions
- Out-of-scope: UI execution dashboards

## Verification Plan

1. Executable confirmed drafts run through the workflow engine.
2. Execution results retain draft, plan, and trace identifiers.
3. Non-executable drafts are rejected before execution.
4. Focused tests and static checks pass.
