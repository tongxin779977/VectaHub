# P1-009: 实现 WorkflowDraft 持久化、读取和列表

> Status: done
> Priority: P1
> Source: Architecture alignment
> Module: `src/orchestration-plan/draft-storage.ts`, `src/commands/draft.ts`
> Completed: 2026-06-08

## Description

Workflow drafts need a minimal persistence layer so review, confirmation, and later execution flows can load and manage previously generated drafts.

The storage and draft command support were already implemented and tested, but the backlog item file was missing.

## Expected

- Persist workflow drafts as JSON records.
- Load drafts by id.
- List drafts and filter by `planId`.
- Update and delete persisted drafts.

## Scope

- In-scope: save, get, list, update, and delete draft operations
- In-scope: list-by-plan-id support
- In-scope: persisted confirmation and metadata round-tripping
- Out-of-scope: remote draft storage
- Out-of-scope: concurrency locking for multiple writers

## Verification Plan

1. Saved drafts can be retrieved by `draftId`.
2. Listing and plan-id filtering return the expected persisted drafts.
3. Update and delete operations behave correctly.
4. Draft metadata and confirmation state round-trip through storage.
