# P2-005: Native Feature Passthrough Policy

> Status: done
> Priority: P2
> Source: Custom rule / skill / MCP ecosystem reassessment
> Module: `docs/contracts/native-feature-passthrough-policy.md`
> Completed: 2026-06-08

## Description

Define the policy for when native VectaHub features may be exposed through custom rules, skills, MCP tools, or other external capability surfaces.

The current ecosystem reassessment references this task as a required foundation, but the policy itself is not yet written or verified. Until this task is completed, custom rule, custom skill, and MCP ecosystem work must be treated as deferred planning rather than implementation-ready capability.

## Expected

- Define passthrough categories for native features: allowed, confirm-required, deferred, and forbidden.
- Define safety, permission, confirmation, trace, audit, and verification requirements for each category.
- Define how passthrough decisions map onto existing command safety, workflow execution, and recovery contracts.
- Define boundaries between built-in features and future third-party capability surfaces.
- Keep custom rule, skill, and MCP ecosystem documents aligned with the policy status.

## Scope

- In-scope: native feature passthrough policy documentation
- In-scope: passthrough category matrix for custom rules, custom skills, and MCP tools
- In-scope: safety and verification acceptance criteria
- In-scope: permission and confirmation requirements
- In-scope: references from ecosystem assessment documents
- Out-of-scope: implementing custom rule, skill, or MCP runtime support
- Out-of-scope: changing command execution behavior
- Out-of-scope: introducing new third-party tool integrations

## Verification Plan

1. Documentation links resolve with `npm run check:docs`.
2. The policy clearly distinguishes current behavior from planned work.
3. The policy defines concrete entry conditions for custom rules, custom skills, and MCP passthrough.
4. Future implementation tasks can reference concrete safety, confirmation, trace, and verification requirements from this policy.
