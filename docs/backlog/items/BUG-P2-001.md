# BUG-P2-001: 意图路由生成未注册命令

> Status: done
> Priority: P2
> Source: E2E Test T2 (Workflow Core)
> Discovered: 2026-06-08
> Completed: 2026-06-08
> Module: `src/nl/`

## Description

`vectahub run "list all files in current directory"` 意图被路由为 `vectahub tool run ls`，该命令不存在于 CLI 注册表中，导致 dispatch 被 blocked。

## Reproduction

```bash
npx tsx src/cli.ts run --dry-run --json "list all files in current directory"
```

## Expected

意图路由生成有效的 CLI 命令，或回退到安全的替代方案（如 `ls` 直接执行）。

## Actual

```json
{
  "kind": "blocked",
  "reason": "generated VectaHub command is not registered: vectahub tool run ls",
  "suggestedAction": "该意图路由生成了当前 CLI 不存在的命令，应回退到任务分诊或文档/Agent 任务体系。"
}
```

## Impact

文件操作类意图（list files、find files 等）无法通过自然语言执行。系统已正确识别为 blocked，不会执行错误命令，但用户体验差。

## Root Cause

`EXTRA_INTENT_MAPPINGS.tool_run` 在 `src/nl/tool-calling.ts` 中将 `tool_run` 意图映射为 `vectahub tool run {{toolName}}`，但 `tool` 不是已注册的 VectaHub 子命令。`run-dispatch.ts` 的 `validateStep` 检查 `args[0]` 是否在 `VECTAHUB_COMMANDS` 中，`tool` 不在其中，因此被 blocked。

## Scope

- In-scope: `src/nl/` 意图路由映射表、命令生成逻辑
- Out-of-scope: `vectahub tool run` 子命令注册（可能是有意未实现）

## Verification Plan

1. `"list all files"` 意图生成可执行的命令或给出明确回退建议
2. `--json` 输出中 `kind` 不为 `blocked`

## Completion

### Changes

- `src/nl/tool-calling.ts`: `EXTRA_INTENT_MAPPINGS.tool_run` 的 `args` 从 `['tool', 'run', '{{toolName}}']` 改为 `['run-command', '{{toolName}}']`，使用已注册的 `run-command` 子命令
- `src/nl/tool-calling.test.ts`: 新增 `tool_run` 步骤生成测试和缺少 `toolName` 的错误测试
- `src/commands/run-dispatch.test.ts` (新增): 验证 `tool_run` 步骤不再被 blocked，`run-command` 子命令通过验证
