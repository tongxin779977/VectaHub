# BUG-P3-001: `templates list` 未发现本地模板

> Status: done
> Priority: P3
> Source: E2E Test T7 (Tools & Templates)
> Discovered: 2026-06-08
> Completed: 2026-06-08
> Module: `src/commands/templates.ts`

## Description

`vectahub templates list` 显示 0 个模板，但项目 `templates/` 目录下有 7 个 YAML 文件（git-commit.yaml、ci-check.yaml 等）。

## Reproduction

```bash
npx tsx src/cli.ts templates list
# 输出: Total: 0 template(s) / (no templates found)

ls templates/
# git-commit.yaml  ci-check.yaml  docker-build.yaml  git-flow.yaml  ...
```

## Expected

`templates list` 应列出 `templates/` 目录下的 YAML 文件作为可用模板。

## Actual

显示 0 个模板。可能 templates list 仅搜索已注册/安装的模板，不包含项目内置模板。

## Impact

用户无法通过 `templates list` 发现和使用项目内置模板。需手动查看 `templates/` 目录。

## Root Cause

`getTemplatesDir()` 函数使用 `context.environment.getPath()` 计算内置模板目录路径。`getPath()` 是基于 `~/.vectahub/` 主目录拼接路径的（`join(getHomePath(), ...segments)`），不适合用于文件系统相对路径计算。导致计算出的路径如 `~/.vectahub/path/to/src/commands/../../../templates` 不存在，`listTemplates` 中 `readDir` 抛异常被 catch 后返回空数组。

## Scope

- In-scope: `src/commands/templates.ts` 中 `getTemplatesDir()` 的路径计算
- Out-of-scope: 模板安装/市场功能、`src/workflow/template.ts`（权威源码不变）

## Verification Plan

1. `templates list` 显示 `templates/` 目录下的内置模板
2. `templates use git-commit` 能实例化内置模板

## Completion

### Changes

- `src/commands/templates.ts`:
  - `getTemplatesDir()`: 将 `context.environment.getPath(__filename, '..')` 改为 `context.environment.getDirname(__filename)`
  - `getTemplatesDir()`: 将 `context.environment.getPath(__dirname, '..', '..', '..', 'templates')` 改为 `context.environment.joinPath(__dirname, '..', '..', 'templates')`
  - 修正路径层级：从 `src/commands/` 到项目根只需 2 级 `..`
- `src/workflow/template.test.ts`:
  - 新增测试：`should list built-in project templates`，验证 `listTemplates` 能从项目 `templates/` 目录发现模板

### Verification Evidence

- Typecheck: `npx tsc --noEmit` 通过（0 errors）
- Tests: `npx vitest run src/workflow/template.test.ts src/commands/templates.test.ts` 全部 21 个测试通过
- CLI 验证: `npx tsx src/cli.ts templates list` 正确显示 7 个内置模板
