# P0-006: 统一机器响应和错误 JSON envelope

> Status: done
> Priority: P0
> Source: Architecture alignment
> Module: `src/infrastructure/errors/index.ts`, `src/machine-response/index.ts`, `src/cli-error-handler.ts`
> Completed: 2026-06-08

## Description

The repository had two overlapping machine-readable error shapes:

1. `machine-response` envelope with `schemaVersion`, `result`, and `timestamp`
2. legacy `toJSONError()` output with only `ok` and `error`

This drift made top-level CLI JSON errors structurally inconsistent with the orchestrator machine-response contract.

## Expected

- Top-level JSON error output includes envelope metadata (`schemaVersion`, `timestamp`) and a structured `result` shape.
- Existing `error` details remain available for compatibility.
- JSON consumers can rely on a single envelope style for success and failure paths.

## Scope

- In-scope: top-level JSON error envelope shape
- In-scope: compatibility-preserving error payload extension
- In-scope: CLI error handler output alignment
- Out-of-scope: rewriting all command outputs to one formatter

## Verification Plan

1. `toJSONError()` returns a standardized envelope with `schemaVersion`, `result`, and `timestamp`.
2. CLI JSON error handling still returns a single valid JSON object.
3. Existing tests for JSON parsing and error serialization continue to pass.
