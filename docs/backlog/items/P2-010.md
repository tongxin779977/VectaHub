> Completed: 2026-06-08

## Description

The orchestration path needs a stable trace-identity chain from plan creation through draft persistence, execution records, and recovery records so failures and follow-up actions remain linkable across the whole lifecycle.

The plan, draft, and execution links were already implemented, and the recovery trace fields were already present in orchestration recovery contracts. This round confirmed the end-to-end evidence chain and backlog tracking.

## Expected

- Plans carry trace identity and audit-event linkage.
- Drafts preserve plan trace identity and plan identifiers.
- Execution records retain trace, plan, and draft identifiers.
- Recovery records preserve source trace identity and attach recovery trace identity.

## Scope

- In-scope: plan trace link contract
- In-scope: draft trace propagation
- In-scope: execution-record trace identity
- In-scope: orchestration recovery trace fields
- Out-of-scope: trace visualization UI
- Out-of-scope: cross-process distributed tracing backend

## Verification Plan

1. Plan trace IDs are preserved when converting to drafts.
2. Saved drafts retain trace identity and plan linkage.
3. Execution records retain `traceId`, `planId`, and `draftId`.
4. Recovery records preserve `sourceTraceId` and `recoveryTraceId`.
