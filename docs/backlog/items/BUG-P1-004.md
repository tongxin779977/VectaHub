# BUG-P1-004: Redactor 过度脱敏 trace/span ID

> Status: done
> Priority: P1
> Source: E2E Test T5 (Logging System)
> Discovered: 2026-06-08
> Completed: 2026-06-08
> Module: `src/security-protocol/redactor.ts`, `src/infrastructure/trace/writer.ts`

## Description

新写入的 trace 数据中，traceId 和 spanId 被 redactor 脱敏为 `[REDACTED]`（如 `tr_[REDACTED]06_t7rwse`），而旧数据（2026-05-13 及之前）保留完整 ID。Redactor 将 ID 中的时间戳部分识别为敏感数据并脱敏。

## Reproduction

```bash
# 查看新数据（被脱敏）
head -1 ~/.vectahub/logs/traces/2026-05-27.jsonl
# 输出: "traceId":"tr_[REDACTED]06_t7rwse"

# 查看旧数据（未脱敏）
head -1 ~/.vectahub/logs/traces/2026-05-13.jsonl
# 输出: "traceId":"tr_1778657109751_8y5jbd"
```

## Expected

traceId 和 spanId 是内部关联标识，不应被脱敏。保持完整 ID 以支持 trace 查询和关联分析。

## Actual

新数据的 traceId/spanId 中间部分被替换为 `[REDACTED]`，导致：
1. `trace list` 显示的 ID 无法直接复制用于 `trace show`（需加引号转义 `[` `]`）
2. trace 间关联分析困难（ID 不完整）
3. `trace show` 查找时需使用脱敏后的 ID

## Impact

Trace 系统的可用性严重下降，ID 是 trace 关联的核心标识，脱敏后丧失关联能力。

## Root Cause

Redactor 的 `PHONE_PATTERN = /1[3-9]\d{9}/g` 匹配中国手机号（11位数字），但 traceId/spanId 中的 `Date.now()` 时间戳包含的数字序列（如 `1778657109`）恰好匹配该模式，导致被误脱敏。`redactObject` 递归处理所有字符串值，不区分 ID 字段和敏感数据字段。

## Scope

- In-scope: `src/security-protocol/redactor.ts` 脱敏配置、`src/infrastructure/trace/writer.ts` 调用 redactor 的方式
- Out-of-scope: audit 日志的脱敏（audit 脱敏是预期行为）

## Verification Plan

1. 新写入的 trace 数据中 traceId 和 spanId 保持完整
2. `trace list` 显示的 ID 可直接用于 `trace show`
3. 脱敏规则仍正确处理真正的敏感字段（如 command 中的 API key）

## Completion

### Changes

- `src/security-protocol/redactor.ts`:
  - `RedactionConfig` 接口新增 `skipKeys?: string[]` 字段
  - `Redactor` 类新增 `skipKeys: Set<string>` 私有属性，构造时从 config 初始化
  - `redactValue` 方法处理对象时，若字段名在 `skipKeys` 中则跳过脱敏
- `src/infrastructure/trace/writer.ts`:
  - Redactor 实例化时传入 `skipKeys: ['traceId', 'spanId', 'parentSpanId']`
- `src/security-protocol/redactor.test.ts`:
  - 新增 `skipKeys` describe 块，4 个测试用例
- `src/infrastructure/trace/writer.test.ts` (新增):
  - 验证 traceId/spanId/parentSpanId 不被脱敏
  - 验证 attributes 中的敏感数据仍被脱敏
