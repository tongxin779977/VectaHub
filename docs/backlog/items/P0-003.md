# P0-003: 建立 `WorkflowDraft` 运行时 schema

> Status: done
> Priority: P0
> Source: Architecture alignment
> Module: `src/orchestration-plan/workflow-draft-adapter.ts`, `src/commands/run-dry-run-envelope.ts`
> Completed: 2026-06-08

## Description

`WorkflowDraft` 类型和 Zod schema已存在于 `src/types/workflow-draft.ts` 和 `src/orchestration-plan/workflow-draft-validator.ts`，但运行时边界（`run --dry-run --json` 输出）仍使用松散类型：

1. `RunDryRunResultWorkflowDraft.workflow` 类型为 `{ name: string; steps: Array<{ cli: string; args: string[] }> }`，与类型化的 `WorkflowDraft` 不一致
2. `buildWorkflowDraftEnvelope` 和 `buildStepsEnvelope` 接受/产出松散类型
3. `run.ts` 中构造松散对象传入 envelope builder，未使用 `WorkflowDraft` 类型

这与 P0-002 的问题模式一致：`RunDryRunResultPlan.plan` 曾为 `Record<string, unknown>`，P0-002 通过 `executionPlanToOrchestrationPlan` 适配器将其改为类型化的 `OrchestrationPlan`。

## Expected

- `run --dry-run --json` 的 workflow_draft 输出为符合 Zod schema 验证的 `WorkflowDraft`
- 适配函数在运行时边界执行 schema 验证
- `RunDryRunResultWorkflowDraft.workflow` 类型从松散类型改为 `WorkflowDraft`
- `buildWorkflowDraftEnvelope` 和 `buildStepsEnvelope` 产出类型化的 `WorkflowDraft`

## Scope

- In-scope: `src/orchestration-plan/workflow-draft-adapter.ts` 适配函数（新增）
- In-scope: `src/commands/run-dry-run-envelope.ts` 类型定义和 builder 函数
- In-scope: `src/commands/run.ts` 调用方更新
- In-scope: `src/orchestration-plan/index.ts` 导出
- Out-of-scope: `WorkflowDraft` 类型定义的修改
- Out-of-scope: `WorkflowDraft` Zod schema 的修改
- Out-of-scope: `MachineResponseEnvelope` 中 `MachineResponseWorkflowDraft` 的修改（已使用 `WorkflowDraft` 类型）

## Verification Plan

1. `stepsToWorkflowDraft` 适配结果通过 Zod schema 验证
2. `buildWorkflowDraftEnvelope` 输出包含 `WorkflowDraft` 结构（`schemaVersion`, `draftId`, `steps`, `safetyReview` 等）

4. `run --dry-run --json --file` 输出 `result.workflow` 为 `WorkflowDraft`
