## Description

The orchestration path needs a reusable feedback record store so user corrections, semantic E2E failures, and execution outcomes can be retained and replayed into eval or backlog proposal flows.

The storage and replay-candidate support were already implemented and tested, but the backlog item file was missing.

## Expected

- Create normalized `NLFeedbackRecord` objects.
- Persist and retrieve feedback records.
- Filter feedback by source and `appliedTo`.
- Export replay-candidate summaries for downstream governance/eval loops.

## Scope

- In-scope: feedback record creation
- In-scope: save, get, list, filter, delete operations
- In-scope: replay-candidate export
- Out-of-scope: automated replay execution
- Out-of-scope: remote/shared feedback storage

## Verification Plan

1. Feedback records can be created and persisted.
2. Filters by source and `appliedTo` return the expected results.
3. Replay-candidate export returns compact summaries.
