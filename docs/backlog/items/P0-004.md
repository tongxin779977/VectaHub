# P0-004: 建立 NL request envelope 和入口 normalization 合同

> Status: done
> Priority: P0
> Source: Architecture alignment
> Module: `src/nl/core/input-normalizer.ts`, `src/nl/core/nl-request-validator.ts`, `src/commands/run.ts`
> Completed: 2026-06-08

## Description

`NLRequestEnvelope` 类型和 `buildNLRequestEnvelope()` 函数已存在于 `src/types/nl.ts` 和 `src/nl/core/input-normalizer.ts`，但存在以下问题：

1. `NLRequestEnvelope` 没有 Zod schema，无法在运行时边界进行结构验证
2. `buildNLRequestEnvelope()` 未被 `run.ts` 命令层调用，NL 请求不经过 envelope 合同边界
3. `normalizeInput()` 仅在 `buildNLRequestEnvelope` 内部调用，未被命令层使用
4. 与 P0-001/002/003 的输出侧合同不对称：输出侧已有 `OrchestrationPlanSchema` 和 `WorkflowDraftSchema` 运行时验证，但输入侧没有

## Expected

- `NLRequestEnvelope` 有 Zod schema，可在运行时边界验证请求结构
- `validateNLRequestEnvelope()` 函数提供与 `validateOrchestrationPlan` 一致的验证接口
- `run.ts` NL intent 路径通过 `buildNLRequestEnvelope` 构造请求，经过验证后再进入编排
- 输入侧和输出侧的合同验证模式对称

## Scope

- In-scope: `src/nl/core/nl-request-validator.ts` Zod schema 和验证函数（新增）
- In-scope: `src/nl/core/input-normalizer.ts` 导出调整
- In-scope: `src/commands/run.ts` NL intent 路径集成 envelope
- In-scope: `src/nl/core/input-normalizer.test.ts` 测试更新
- In-scope: `src/nl/core/nl-request-validator.test.ts` 验证测试（新增）
- Out-of-scope: `NLRequestEnvelope` 类型定义的修改
- Out-of-scope: `orchestrateIntent` 内部逻辑的修改
- Out-of-scope: `--file` 路径的修改（file 路径不走 NL envelope）

## Verification Plan

1. `validateNLRequestEnvelope` 对合法 envelope 返回 `valid: true`
2. `validateNLRequestEnvelope` 对缺失必填字段的 envelope 返回 `valid: false` 和具体错误
3. `run.ts` NL intent 路径构造并验证 `NLRequestEnvelope`
4. 验证失败的请求不进入编排
5. Typecheck 通过
6. 所有相关测试通过

## Completion

### Changes

- `src/nl/core/nl-request-validator.ts` (新增):
  - `NLRequestEnvelopeSchema` Zod schema：验证 `schemaVersion`、`requestId`、`source`、`mode`、`dryRun`、`json`、`cwd`、`userInput`、`normalizedInput`、`sessionId`、`contextId`、`metadata`
  - `NormalizedInputSchema` 和 `NormalizedInputEntitiesSchema` 子 schema
  - `validateNLRequestEnvelope()` 函数：schema 验证 + 业务规则验证
  - `validateUserInputNotEmpty()`：非 manual source 不允许空输入
  - `validateModeConsistency()`：mode 和 dryRun 标志必须一致
  - `NLRequestValidationError` 和 `NLRequestValidationResult` 接口
- `src/commands/run.ts`:
  - 导入 `buildNLRequestEnvelope` 和 `validateNLRequestEnvelope`
  - NL intent 路径：在 `orchestrateIntent` 调用前构造 `NLRequestEnvelope` 并验证
  - 验证失败时通过 `exitWithError` 退出，不进入编排
  - `cwd` 改为从 envelope 获取
- `src/nl/core/nl-request-validator.test.ts` (新增):
  - 17 个测试用例覆盖 schema 验证和业务规则验证
