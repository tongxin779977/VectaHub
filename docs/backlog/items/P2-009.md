# P2-009: Workflow snapshot/hash guard

> Status: done
> Priority: P2
> Source: Architecture alignment

> Completed: 2026-06-08

## Description

Draft execution and orchestration recovery need a stable workflow-hash guard so resume, rerun, and recovery decisions can detect stale workflow definitions and fail closed when the current workflow no longer matches the stored execution context.

The workflow-hash generation, execution-record persistence, and recovery-time mismatch blocking were already implemented and tested, but the backlog item file was missing.

## Expected

- Generate a stable `workflowHash` from executable workflow structure.
- Persist `workflowHash` in workflow drafts and execution records.
- Validate the current workflow against the stored execution hash.
- Block orchestration recovery when plan or workflow hashes no longer match.

## Scope

- In-scope: workflow hash computation
- In-scope: execution-record hash persistence
- In-scope: hash mismatch validation helpers
- In-scope: recovery decision blocking on stale hash context
- Out-of-scope: git snapshot diffing
- Out-of-scope: cross-project remote recovery coordination

## Verification Plan

1. Equivalent workflows produce identical hashes.
2. Workflow changes produce different hashes.
3. Draft execution writes the computed workflow hash into the execution record.
4. Recovery decisions block when plan/workflow hash inputs mismatch.
